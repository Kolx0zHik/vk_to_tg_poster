## 2. В процессе (где остановились)

- **Редизайн логов (1.1.16) — влита в `main`, тег `v1.1.16`.** Сделано: структурный журнал запусков (`src/journal.py`,
  `data/runs.json`), возврат сводок из `process_communities`, `GET /api/journal`, структурированный
  `/api/logs`, вкладки «Журнал запусков»/«Технический лог», статус последнего запуска в шапке,
  очеловеченная итоговая строка файлового лога, эмодзи-значки ✅/❌, имена сообществ вместо сырых
  owner id в вердиктах дублей, +10 тестов. Осталось: проверить вид журнала в браузере на живом
  прод-прогоне после обновления контейнера; открытым остался вопрос фильтра журнала по отдельному
  сообществу.
- **Ветка `feature/semantic-dedup` — влита в `main` (v1.1.15, 2026-09-29).** Реализованы ИИ-проверка дублей до публикации (включая настраиваемый
  системный промпт `llm.prompt`) и перенос секретов в `.env` (ADR-017, ADR-018). Проведён полный аудит ветки
  (2026-09-21): исправлены два бага — `DELETE /api/community/{id}` затирал секцию `llm` в конфиге, кандидаты
для LLM передавались в формате, не совпадающем с описанием в промпте (`owner_id/post_id/text` вместо
   `chat_id/message_id/raw_text`); добавлены регресс-тесты. 2026-09-22 добавлено нормирование размера
   `cache.json` (ADR-019): cap текстов ИИ-пула, прунинг вне флага и архивация терминальных записей старше
   30 дней в `archived`-tombstones. 2026-09-23 встроенный `DEFAULT_SYSTEM_PROMPT` удалён (ADR-020): промпт
   в `llm.prompt` обязателен, без него проверка не работает (warning в лог; 400 на сохранение «включено без
   промпта»). Тогда же пересмотрен контракт кандидатов и ответа LLM (ADR-021): вычищены n8n-поля
   `chat_id`/`message_id`/`date_unix`/`raw_text` и неиспользуемый `matched_message_id`; кандидаты нумеруются
   и ограничиваются чар-бюджетом по границам записей, `matched` — номер кандидата, который пайплайн маппит
   на исходный пост для лога; формат ответа задаёт код (`ANSWER_CONTRACT` в user-message), в `llm.prompt`
   остаются только критерии дубля. 2026-09-23 `.env` очищен до только-секретов (ADR-022): `TZ` →
   `general.timezone` (поле+валидация в панели, применяется через `apply_timezone`, перечитывается в цикле),
   `LLM_DEBUG_LOG` → `general.semantic_dedup.debug_log` (тумблер в «ИИ-проверка»), `envfile` игнорирует
   legacy-ключи. 2026-09-24 первый запуск стал бесшовным (ADR-023): bootstrap-`config.yaml`
   (`default_config()`) и `config/config.example.yaml` seeds с заполненной секцией `llm` — OpenRouter base_url,
   модель и стартовый промпт `STARTER_LLM_PROMPT` (только правила дубля; JSON-контракт добавляет код).
   Влита в `main` fast-forward 2026-09-29 и помечена аннотированным тегом `v1.1.15`; CI собирает `:latest`.
- **Редизайн блока «Основные настройки».** Готовы 4 макета (плитки / строки / две колонки / секции) и
  скриншоты десктоп+телефон в `.playwright-mcp/settings-variants/` (в git не попадают). Решение
  отложено: «оставляем пока как есть». При доработке важно: блоки идут друг под другом во всю ширину,
  на 390px не должно быть горизонтального скролла.
- **Список LLM-моделей в панели.** Поле «Модель» в модалке «ИИ-проверка» получило комбобокс: при фокусе
  загружает `{base_url}/models` через `GET /api/llm/models?base_url=` с `LLM_API_KEY` из `.env`, позволяет
  выбрать модель кликом и фильтрует список по подстроке (например `free`) без учёта регистра. Ключ уходит
  только на сохранённый `llm.base_url`; новый адрес нужно сначала сохранить, иначе 400 (ADR-024).
- **Обновление прода.** Владелец обновляет вручную: `docker compose pull && docker compose up -d`.

## 3. Сломано / временное / известные баги

Приоритеты: 🔴 теряем данные/публикации · 🟠 заметно пользователю · 🟡 мелочь.

| # | Что | Где | Приоритет |
|---|---|---|---|
| 1 | Альбом из >10 фото не разбивается на части — Telegram вернёт ошибку, пост уйдёт в `pending` и будет повторяться до `dead` | `src/tg_client.py` `send_post`/`send_media_group` | 🟠 |
| 3 | Частичная отправка: если альбом ушёл, а текст упал, повтор отправит всё заново → дубли в канале | `src/pipeline.py` `_publish_pending` | 🟠 |
| 4 | Видео с картинкой из VK отправляется как фото-превью с caption-ссылкой, а не как файл/видео. Причина: URL `player` из VK API — это страница плеера, а не прямая ссылка на видеофайл; Telegram не может скачать видео с VK по этой ссылке. Если VK не отдаст `image`/`first_frame`, останется текстовая ссылка без гарантированного превью Telegram | `src/vk_client.py`, `src/tg_client.py` | 🟠 |
| 5 | Медиагруппа: если хоть одно фото >10 МБ или не скачалось, вся группа отправляется по URL (для VK-ссылок это обычно отказ) | `src/tg_client.py` `send_media_group` | 🟠 |
| 6 | Поддерживаются только `photo/video/audio/link`; `doc`, опросы, стикеры, записи на стене и прочее молча отбрасываются | `src/vk_client.py` `_parse_attachments` | 🟠 |
| 7 | Дедупликация глобальная: один пост из двух сообществ публикуется один раз | `src/cache.py` | 🟡 (осознанно) |
| 8 | `ContentTypes` по умолчанию `audio: true`, а интерфейс сохраняет `audio: false` — загруженный вручную конфиг без секции типов включит аудио | `src/config.py` vs `static/script.js` | 🟡 |
| 9 | Удаление сообщества убирает его из конфига (`DELETE /api/community/{id}`), но не чистит состояние в `cache.json` (намеренно). Неограниченного накопления больше нет: терминальные записи старше 30 дней схлопываются в `archived` (ADR-019), но tombstones удалённых сообществ всё равно остаются | `src/web.py` `_cleanup_cache` — заглушка | 🟡 |
| 10 | Веб-панель без аутентификации: кто дотянулся до порта 8222, тот видит и меняет конфиг (токены маскируются в ответе). `GET /api/llm/models` больше не шлёт `LLM_API_KEY` на произвольный `base_url` из запроса — только на сохранённый (ADR-024), но аутентификации по-прежнему нет | `src/web.py` | 🟠 (при публикации в интернет) |
| 11 | `is_pinned` парсится, но нигде не используется: закреплённый пост может попадать в выборку каждый цикл (повторно не публикуется за счёт дедупа) | `src/vk_client.py` / `src/pipeline.py` | 🟡 |
| 12 | Временное: тумблер `general.semantic_dedup.debug_log` (панель «ИИ-проверка», ADR-022) пишет в INFO вердикт «не дубль» по каждому посту (дубли логируются единственной строкой и без него); сырой ответ LLM — только при неразобранном JSON. Снять после тестов (CHANGELOG → 1.1.15) | `src/dedup.py`, `src/pipeline.py` | 🟡 временно |

Баг №2 (длинный текст >4096) закрыт в 1.1.10: как и caption, текст обрезается до 1024 с пометкой о
продолжении; номер сохранён для ссылок из ROADMAP/CHANGELOG.

## 4. Чего мы НЕ проверяли (не считать проверенным)

- Реальную дозаливку из VK и доставку в Telegram, включая живое видео-превью: локально нет валидных токенов, end-to-end прогонов не было.
- Поведение при >10 фото, при аудио без URL.
- Работу `:latest` в проде после обновления (образ собирается CI, прод обновляет владелец).
- Удаление сообщества через веб-панель в браузере (модалка → `DELETE /api/community/{id}`): покрыт только
  сам обработчик юнит-тестами, клик в UI не проверялся.
- Восстановление после сбоя питания/убийства процесса посреди публикации (атомарность записей есть, поведение не тестировалось).
- **ИИ-проверку дублей с реальным LLM**: проверены только парсинг ответа, ретраи и fail-open на моках;
  качество промпта и ложные срабатывания на живых постах не оценивались.
- **Чтение `.env` в контейнере**: локально проверено юнит-тестами, но реальный докер-прогон с
  `data/.env` и перезапуском после смены секрета не выполнялся.
- **Сохранение/загрузку настроек ИИ из веб-панели**: обработчики и модели обновлены, клик по модалке
  «ИИ-проверка» в браузере (включая поле системного промпта) не проверялся.
- **Журнал запусков в браузере на живых данных**: рендер карточек/событий проверен на синтетическом
  `runs.json`; реального запуска с публикацией в VK/Telegram (валидных токенов нет) не было, поэтому
  вид журнала на настоящем прогоне не подтверждён.

## 5. Как обновлять этот файл

После значимого изменения: поднять версию в `VERSION`, обновить разделы 1–3, отметить в разделе 4, что
осталось непроверенным, добавить строку в [CHANGELOG.md](./CHANGELOG.md) и, если решение меняет
архитектуру, — запись в [DECISIONS.md](./DECISIONS.md). Форматы файлов состояния описывать в
[ARCHITECTURE.md](./ARCHITECTURE.md), а не здесь.
